## 🧪 Testing A New Build Safely

A new build should be proven before it is trusted in a real session.

**The order**

1. Extract to a fresh folder — do not overwrite the working copy.
2. Run with everything disabled and confirm the menu opens.
3. Enable one module, confirm it works, then close.
4. Relaunch and confirm the setting persisted.
5. Only then copy your presets across from the old folder.

**Why the fresh folder matters**

Overwriting the working copy means a bad build destroys a good configuration.
Two folders side by side costs a few hundred megabytes and gives you a rollback
that takes one rename.

**The persistence test**

Step 4 is the one people skip. A build that works but does not save settings is
worse than one that fails outright, because you only discover it after
re-tuning everything.

**What "works" means per module**

| **Module** | **Pass condition** |
| --- | --- |
| Overlay | draws and updates |
| Assist | responds to the configured key |
| Cosmetic | item changes and stays changed |
| Identity | values differ after reboot |

**Rolling back**

If the new build misbehaves, close everything, rename the new folder to
`broken`, rename the old one back. Nothing else is required — there is no
installer state to unwind.

did nothing" when they simply never restarted.
